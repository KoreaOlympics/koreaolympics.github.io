# 세계선수권 메달 자동 연동 게시 안내

다음 파일을 기존 KoreaOlympics 저장소에 **같은 경로로 추가·병합**하세요. 기존 사이트 전체 파일은 그대로 필요합니다.

- `index.html`: 기존 공개 목차에 ‘최신 세계선수권 메달 · 한국’ 진입 카드 추가.
- `worlds-medals.html`: 국가별 순위, 한국 메달 상세, 선수·세부종목 원본 설명 링크. 검색과 메달 필터 포함.
- `data/worlds-medals.json`: 실제 원본에서 수집한 최초 데이터.
- `scripts/update-worlds-medals.py`: 외부 패키지 없이 실행하는 수집·검증 프로그램.
- `.github/workflows/worlds-medals.yml`: 15분 간격으로 수집 후 저장소 전체 정적 사이트를 GitHub Pages에 배포하는 작업.

## 최초 설정

1. ZIP을 풀고 숨김 폴더인 `.github`를 포함해 위 경로대로 저장소 기본 브랜치에 올립니다.
2. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 설정합니다.
3. Actions에서 **Refresh world championship medals and publish site**를 찾아 **Run workflow**로 한 번 실행합니다.
4. `https://koreaolympics.github.io/worlds-medals.html`과 목차의 새 카드를 확인합니다.

이미 GitHub Pages 배포 워크플로가 있다면 두 작업이 서로 다른 결과를 배포하지 않도록 기존 작업에 수집 단계를 통합하세요. 제공한 작업은 저장소 루트를 정적 사이트로 배포하는 구성이며, Jekyll 등 별도 빌드가 있는 저장소에서는 기존 빌드·배포 단계를 유지하고 수집 단계만 앞에 추가해야 합니다.

## 자동 반영 범위

Totallympics는 외부 사이트의 iframe 삽입을 막고 브라우저 직접 요청용 CORS 헤더도 제공하지 않았습니다. HTML만 업로드해서 외부 데이터를 즉시 읽는 방식 대신 서버 측인 GitHub Actions가 원본을 수집합니다.

작업은 매시 07·22·37·52분에 예약되고, 화면은 1분마다 게시된 JSON을 다시 확인합니다. GitHub 예약 실행 지연, 원본의 약 15분 캐시, 차단·오류가 있을 수 있어 즉시 반영이나 정확한 15분 이내 갱신을 보장하지 않습니다. 예약 작업은 기본 브랜치에서 실행되며 실제 활성화는 저장소에 올리고 설정한 뒤에 이루어집니다. 이 제공본은 아직 게시하거나 자동 작업을 활성화하지 않았습니다.

수집 실패 시 배포를 중단해 마지막 정상 게시 자료를 유지합니다. 표 구조가 달라지거나 합계 검증이 실패해도 중단합니다. 화면은 수집 시각, 1시간 경과 상태, 확인 실패 상태를 표시합니다. 원본의 내용 수정 시각과 자료 수집 시각은 다릅니다.

## 집계 해석

전체 순위는 종목별 **최신 세계선수권**을 합친 것으로, 새 대회가 반영되면 이전 대회를 교체합니다. 누적 메달이나 올림픽 출전권이 아닙니다. 한국 상세 표의 `Expired` 기록은 기본 화면에서 숨기며 사용자가 포함할 수 있습니다. 날짜로 남아 있는 만료 기한을 임의로 수정하지 않습니다. 전체 합계와 상세표의 값이 다르면 양쪽 값을 안내합니다.

최초 수집에서 국가 97개, 한국 상세 원문 44건(Expired 제외 36건)을 읽었습니다. 이후의 값은 원본을 따라 바뀝니다. 국가·선수 이름과 기한은 원문을 유지하고 설명은 한국어로 제공합니다.

## 수동 수집

저장소 루트에서 `python scripts/update-worlds-medals.py`를 실행하면 JSON과 HTML의 초기 표시 자료를 함께 갱신합니다. 인증키는 필요하지 않습니다.

로컬 파일로 열면 동봉한 자료를 표시합니다. 자동 갱신은 사이트 게시 및 Actions 설정 후 작동합니다.
